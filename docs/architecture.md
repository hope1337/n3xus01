# Architecture

Windows/Ubuntu hosts use native Python stdlib and OpenSSH. The CLI sends JSON stdin to a short-lived Python helper over Tailscale SSH. No persistent control connection or coordinator/server. Windows JSON/base64 argv preserves quotes, Unicode and dollar signs without shell eval.

Canonical shared config: CLI workspace/config/devices.json with schema/profile/devices. Setup validates/moves a legacy root devices.json without replacing the profile and initializes only host config. Local workload roots live outside the tool repo; project init creates a stable .n3xus-project.json marker and project communication folders, preserving existing files and appending /communication/ to .gitignore. Discovery uses the nearest ancestor marker or exact --project-dir root. Invalid/missing context blocks project writes before remote mutations, never falls back to CLI workspace. Remote state remains ~/.local/share/personal-device/PROFILE, guarded by UID/schema/profile and fingerprints. Updates do not automatically refresh helpers/restart jobs.

Each job has a tmux session on a private socket. Records contain ID, name/description/agent, revision, command/env/GPU, PID/start ticks/boot ID, state/log/output and dated notes. State is checked live; phase/progress are not inferred. Sessions finish with the runner; metadata/log remain until clean. Missing processes/reboots are not completion. Jobs do not auto-resume and personal tmux sessions are not managed. Programs must stay in the foreground.

Jobs defaults to active work. Name lookup prefers active jobs; ambiguous history requires an ID. job_detail includes recent log; job_note writes under a lock without changing command/process. Dashboard polls one overview RPC/device with up to eight concurrent devices and reports observation time/errors, never stale snapshots as live. Native keyboard handling restores terminal/cursor in finally; stop/delete require confirmation. Closing the dashboard leaves jobs running.

Terminal feedback uses scripts/device_progress.py for transient redraws and a spinner during SSH/HTTP waits. Multi-device collectors publish futures as they complete, keeping config order. Read-only probe/overview requests optionally emit newline-delimited progress events: CPU/RAM first, GPU/Conda/linger next, followed by the normal final response. The host drains SSH stdout/stderr concurrently, applies the existing total deadline (including stdin writes), reaps the local SSH process on errors, and never retries a mutation. Missing results have loading placeholders; errors replace placeholders. Other atomic RPC results show a waiting indicator until the response arrives. JSON/non-terminal output disables progress events and retains one final JSON/text response. No permanent host/device process or extra SSH connections are added; installed remote runners are not refreshed for this display feature.

Interactive dashboard refresh owns a full-screen progress renderer instead of appending the generic CLI view below the dashboard. During a refresh, only pending fields/job lists can retain the previous completed observations; the banner explicitly labels them as refreshing/previous values. Fresh partial fields replace cached values immediately. Final errors/offline responses discard cached resource values and jobs. History toggles respect the selected filter. Final snapshots return to the normal observed-time banner. The cache lasts only for the open dashboard session, is never returned as current JSON state and does not feed job actions before the refresh completes.

Each project contains communication/shared, communication/runs and communication/agents/ID/{work,downloads,notes}. Run/serve receipts go to that project; post-submission write failures remain warnings to prevent duplicate submissions. Project snapshots filter job rows by local receipts while device resources/counts remain global. Jobs/dashboard remain global; remote project labels are explicit and should be unique across local projects. Source/output/message-file paths resolve from project root and cannot escape it or follow symlinks; whole-project sync is refused. Default fetch uses agent downloads (human unless specified). Unique handoff files prevent overwrites; snapshot.json/STATUS.md are replaced atomically per file; SUMMARY.md is preserved. Legacy CLI workspace data is untouched, never auto-migrated/adopted. Folder separation organizes data, not access isolation.

Immutable sync revisions and per-job copies protect running code. Secret exclusions prevent common mistakes, not detect all secrets. Large datasets/models stay on device disks. No GPU scheduling/quota/sandbox/pooling/backup. Inspect/reuse existing Conda envs; the eight-managed-env limit is not a disk quota. Cache/code/results/journal still occupy disk.

Optional systemd-user services require linger, owned unit fingerprints, Tailscale bind and a monitored foreground process; KillMode=control-group, Restart=on-failure. No automatic auth/TLS. The runner checks the configured port; untrusted apps can open other ports, so this is not a network sandbox. Verify endpoints with real requests; active alone is insufficient.

## Command registration

Setup installs user launchers pointing to the checkout and resolved Python executable. Windows PowerShell delegates to the repo's argv-preserving launcher; CMD is also supported. Linux execs Python with literal argv. Only user PATH/startup blocks change; no SSH. Markers encode public paths, and generated launcher bodies must match before replacement/removal. Receipts stay in workspace/config; global launchers are the host-runtime placement exception. Preserve/report unowned or modified files. unregister affects only the current checkout registration, independently of config/profile/remote state. Setup migrates exact owned legacy device launchers to n3xus without changing device identity.
